# Opt-in witnessed effect journal V2

`DurableEffectBroker` can use `aether.effect-journal/2` with an `EffectJournalWitness` supplied outside its reloadable adapter factory. The V1 broker and `effects.json` remain unchanged. V2 uses `effects-v2.json`, binds the witness identity (authority, repository, deployment and clock domain), and increments a revision for every durable state transition. Opening a V1 directory as V2, or a V2 directory without its witness, fails explicitly.

The witness API is synchronous because the existing broker dispatch boundary is synchronous. Its provider must implement **atomic, durable compare-and-swap** on the revision and retain the exact complete canonical journal bytes. The broker publishes to the witness before updating its local file or entering a sink. A failed or uncertain witness response throws before sink entry. On reopen, a missing or older local copy is restored from the witness; same-revision divergence and local state ahead of the witness are refused. The anchor also detects witness rollback or equivocation during its own lifetime. The external service must enforce monotonicity across controller restarts and machine restores.

The [focused tests](../../../test/fabric/effect-journal-witness.test.ts) use a local in-memory witness to exercise protocol ordering and recovery. They do **not** establish independent custody. A hostile factory in the same Node process may have ambient access to an in-process provider or its files. Production use requires an OS-separated, authenticated witness or equivalent enforced capability boundary. The service must validate expected deployment, policy, adapter and transition subjects before accepting a new head; a blind CAS callback from a factory is not sufficient.

This V2 slice does not authenticate the external sink's commitment or bind ProcessHost's cached effect record to the witnessed head. The existing `aether.effect-receipt/1` digest is still unkeyed, and `replayEvents` supplied to an isolated broker are not witnessed. A later host profile must require verified broker heads on cached, replayed and recovered outcomes; external writes need authenticated sink status or a trusted executor. Until then, T2-04/G1/G2 and NFR-16 remain open. Historical V1 journals require an explicit, separately authorized migration rather than silent adoption.
