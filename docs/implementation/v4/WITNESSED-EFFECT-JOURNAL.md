# Opt-in witnessed effect journal V2

`DurableEffectBroker` can use `aether.effect-journal/2` with an `EffectJournalWitness` supplied outside its reloadable adapter factory. The V1 broker and `effects.json` remain unchanged. V2 uses `effects-v2.json`, binds the witness identity (authority, repository, deployment and clock domain), and increments a revision for every durable state transition. Opening a V1 directory as V2, or a V2 directory without its witness, fails explicitly.

The witness API is synchronous because the existing broker dispatch boundary is synchronous. Its provider must implement **atomic, durable compare-and-swap** on the revision and retain the exact complete canonical journal bytes. The broker publishes to the witness before updating its local file or entering a sink. A failed or uncertain witness response throws before sink entry. On reopen, a missing or older local copy is restored from the witness; same-revision divergence and local state ahead of the witness are refused. The anchor also detects witness rollback or equivocation during its own lifetime. The external service must enforce monotonicity across controller restarts and machine restores.

The [focused tests](../../../test/fabric/effect-journal-witness.test.ts) use a local in-memory witness to exercise protocol ordering and recovery. They do **not** establish independent custody. A hostile factory in the same Node process may have ambient access to an in-process provider or its files. Production use requires an OS-separated, authenticated witness or equivalent enforced capability boundary. The service must validate expected deployment, policy, adapter and transition subjects before accepting a new head; a blind CAS callback from a factory is not sufficient.

Signed V4 Wasm ProcessHost now reconstructs the exact historical request and compares terminal host effects with the broker through a read-only inspection path. It checks on reopen, same-ID call retry, public result/disposition reads, worker replay and recovery. The [real-worker test](../../../test/tier4/process-wasm-effect.test.ts) uses V2 and refuses a forged local journal at those boundaries. Inspection runs no sink, grant, reconciliation or budget callback. Historical V1 broker use still has only local unkeyed digests; a coordinated rewrite of both V1 stores is not defeated by this comparison.

The opt-in `scoped-anchored-wasm-v8` deployment and `isolated-wasm-v6-witnessed` host profile now bind an operator-held witness catalog into deployment `/8`, prepared `/6`, host configuration `/6` and effect plan `/6`. The catalog selects one exact V2 witness object per effect operation. The signed host checks that object nonvirtually before dispatch, cached result inspection and reconciliation; a broker with replaceable instance methods or a subclass is refused. Deployment also compares settled receipts with the inner host on retry, recovery and reopen; a shortcut discovered by the V8 test was repaired. V7 and earlier bytes remain explicit and unchanged. The [real-worker V8 test](../../../test/tier4/process-wasm-witness.test.ts) covers signed promotion and reopen, wrong witness object, wrong catalog, replaceable broker method, factory-supplied catalog refusal and V7 adoption refusal.

The test catalog and witnesses are still in-process. Production requires an OS-separated witness service with authenticated access, monotonic durable storage across restarts, transition/policy validation and protected key custody. The factory still constructs brokers and could exercise ambient process authority; the exact-object check does not confine hostile JavaScript. The V1 `aether.effect-receipt/1` digest remains unkeyed, isolated `replayEvents` are not independently witnessed, and the external sink's commitment is not authenticated. External writes need authenticated sink status or a trusted executor. Until these boundaries and the full path campaign are satisfied, T2-04/G1/G2 and NFR-16 remain open. Historical V1 journals require an explicit, separately authorized migration rather than silent adoption.
