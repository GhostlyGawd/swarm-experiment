# Opt-in V9 complete journal witnesses

The `scoped-anchored-wasm-v9` deployment profile extends the V8 witnessed Wasm path. A direct host selects `isolated-wasm-v7-host-witness`. Historical V8, V7 and earlier profile bytes remain explicit; a V9 directory cannot be reopened as V8 or adopted silently.

V8 compared broker outcomes only for effects still listed in the local host journal. An adversarial review found that deleting a completed call's `effects` array from `host.json` could make the host report `safeToAbortBeforeEffects: true` while the independently witnessed broker retained a commit. A second review found that deleting an old invocation from `deployment.json` after promotion could permit its operation ID to execute again on the new host. V9 binds the **complete** host journal and deployment invocation/allocation registry to separate operator-supplied monotonic heads, so an omitted row is checked against the full witnessed bytes before a cached result or fresh call is served.

| Boundary | V9 identity and durable format | Publication and read contract |
| --- | --- | --- |
| Broker effect | Namespaced catalog `/2` and per-operation witness `/2`, bound to the same deployment ID as the host and outer witnesses; broker journal `/2` | Exact broker CAS precedes local write and sink entry. Historical V1 witness identities remain explicit under V8. |
| ProcessHost | `HostJournalWitnessCatalog`; host configuration `/7`, complete host journal `/4` with `witnessRevision` | Each journal mutation CASes complete canonical bytes before local publication. A journal object may write only from the exact witness revision it read. Same-revision local divergence fails; older/deleted local bytes are repaired only under a later writer/reopen. |
| ProcessDeployment | `DeploymentJournalWitness`; deployment state `/9` with `witnessRevision`, prepared record `/7`, effect plan `/7` | Every invocation, allocation and promotion state transition CASes the complete registry before local publication. The operator witness digest is bound into state, prepared record and authorized effect plan. |

The host witness identity includes authority, repository, deployment and host IDs. A catalog must select one stable object with all four matching; two deployment namespaces cannot silently reuse a `genesis` host head. The V2 broker witness separately binds its catalog deployment ID and exact operation ID. V9 requires the effect catalog, host catalog and deployment witness to name the same deployment. Witnesses are provisioned outside reloadable service factories, and V9 refuses factory-supplied witness objects. A witness cannot be replaced with a matching label after a directory has been created.

The [real worker V9 test](../../../test/tier4/process-wasm-host-witness.test.ts) exercises direct and deployed Wasm calls, signed promotion, reopen, same-revision host effect omission, outer invocation omission after promotion, older/deleted host copies, older outer state, lost CAS acknowledgment before broker entry, rollback within one witness lifetime and wrong authority/catalog choices. It checks that the broker is not entered on the outer omission. State reads also recheck terminal broker effects before promotion can use a snapshot. The [host witness](../../../test/fabric/host-journal-witness.test.ts), [deployment witness](../../../test/fabric/deployment-journal-witness.test.ts) and [effect witness](../../../test/fabric/effect-journal-witness.test.ts) tests cover canonical bounds, CAS response integrity, stale writers and same-lifetime rollback/equivocation.

These fixtures use in-memory operator heads in one Node process. They prove the protocol behavior under those injected faults, **not** independent custody or durability after controller death. Production qualification still requires an OS-separated authenticated witness service with durable atomic CAS, protected keys, monotonic storage across restarts and machine restores, and validation of expected deployment, policy, adapter and transition subjects. A reloadable factory or hostile JavaScript with the same ambient process authority must not be able to replace or edit that service. The external sink's actual commitment also needs authenticated status or a trusted executor; an unkeyed V1 receipt digest is insufficient. Independent replay witnessing, complete all-path grant schedules and general effectful adapter isolation remain open. V4-T2-04/G1/G2, NFR-16 and the 20/62 task count therefore do not change.

The later [process-external service slice](OS-WITNESS-SERVICE.md) moves those heads to a separate durable process and passes same-UID service SIGKILL/restart with real ProcessHost and ProcessDeployment workers, plus a separate controller SIGKILL/recovery with a read-only Wasm effect. It does not by itself satisfy the distinct-UID, transition, sink or machine-rollback obligations above.
