## Closure order

It does not close the row above: deployed admission/promotion, dynamic operator grant selection, measured charges and the full effect-path matrix remain open. A generic pre-dispatch bridge release still needs a signed fence in this profile. These gaps remain visible even though the focused campaign passes.

1. Target **T1-05 for the next complete-task closure** after the T2-04 budget checkpoint. Its prerequisites are verified and the existing semantic-GC campaign exposes exact missing production work: effect/contract-preserving rewrites, adapter retirement and retention tied to audit, replay, active tasks and unstable replication. Run both complete gates on the admitted production path before changing the task count.
2. Resume **T2-04's remaining V11 crash/fence phases, full external-effect path matrix and deployed budget settlement**. It blocks resource typing and production topology. A signing key or monotonic head inside the reloadable factory would not establish the required independent authority. A signed broker assertion also cannot prove that an external sink acted; authenticated sink status or an isolated trusted executor is required. Historical V1 journals stay explicit.
3. Continue **T3-07** without claiming closure from its bounded prototype. FR-3.7 itself requires an in-frame Tier 1-to-Tier 2 switch within 50 ns; the existing native result is inconclusive at the timer's 41.667 ns resolution, and its bounded record ABI lacks admitted runtime effects and portable proof. Qualify these on a suitable target with G1/G2 before changing the task count.
4. Finish **T1-02's semantic coverage** to unlock cross-layer specifications and their v2 dependents. Keep actual 4× token efficiency as a separate unchanged release result. Continue T2-06 and T3-03 production integration and T3-10 full-runtime work. Recompute the graph and benchmark manifest after each complete gate campaign. Only a passing evidence manifest for every gate changes the 20/62 count.
