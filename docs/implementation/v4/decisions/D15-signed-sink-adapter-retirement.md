# D15 — Governor-admitted signed sink adapter retirement

Status: bounded production T1-05 integration for independently attested sink registrations. T1-05/G1 and G2 remain open; specification 0.1.0 and release thresholds are unchanged.

## Decision and identities

New `aether.declarative-adapter-table/2` entries describe an exact capability, adapter ID and semantics digest, approved sink artifact label, deployment/sink witness identities and a no-unload lifecycle. The complete table is signed indirectly by effect-resource policy `/7`: its body includes the table digest and the exact sorted V6-style sink rules. The execution manifest still binds the signed **policy body** in `capabilityPolicyDigest`; it does not reuse that field for a table digest. An empty V7 rule set requires an independently checked exact-root AST with no `Invoke` anywhere. Existing policy V1–V6 and table V1 bytes remain separate.

The independently checked semantic sink retirement proof `/2` binds source and candidate manifests, signed V7 policies, complete V2 tables, unchanged AST and non-policy manifest fields, formal fences, exported/protected declarations, retained task/replay/unstable roots, the exact removed registrations and a portable dispatch-preservation certificate. A retirement must advance the operator policy epoch strictly. The verifier checks the current retention snapshot before a new decision. Historical audit rechecks the original proof and its still-retained pins while allowing later pins to arrive; it cannot authorize a new commit. The proof itself never selects the live table.

Process artifact `/2` embeds the signed policy, table and nullable proof. Deployment profile `scoped-anchored-sink-v12` witnesses state `/12`, prepared record `/10` and effect plan `/10` with table, policy, proof, candidate and predecessor artifact identities, plus independent signer, clock, sink and journal witness roots. Strict signed lineage and the governor approval are required. The witnessed deployment's active Artifact/2 is the only live table head; the earlier candidate sidecar remains proof and audit infrastructure. The reloadable factory cannot substitute the operator table, signer, sink witness or retention authority. `BrokerEffectRouter` checks its private complete adapter map nonvirtually against the signed table before dispatch; dead/unplaced registered capabilities are checked by synthetic preflight without granting them an execution placement.

The coordinator's synchronous `commitFence` lets deployment recheck source generation, exact proof, signed policies and retention under the semantic-retention lock across the final durable governor decision. A new active-task pin between prepare and commit aborts retirement. After commit, activation closes predecessor hosts before publishing ready. A historical predecessor host reopens with its own signed Artifact/2 for receipt inspection and authorized reconciliation; it cannot accept a new live call or effect. During the required epoch cutover before commit, the stale source is unready for new calls but remains available for administrative reopen, old-receipt inspection and promotion. A committed proof remains auditable after later task pins.

## Scope and remaining gates

The direct campaign exercises a real ProcessHost worker and signed sink adapter through strict-lineage ProcessDeployment, one signed retirement promotion, a new live call, predecessor receipt recovery after reopen, stale-epoch administrative restart and a late retention pin. A second campaign runs separate sink, sink-witness and operator-witness services with short-lived controllers. Actual SIGKILL before and after the durable governor commit is followed by fresh-controller abort or activation recovery; the predecessor receipt is inspected without redispatch, operator witness outage refuses service, and a same-revision local table edit is rejected. These services still share one UID. The profile retains historical artifacts and receipts; it does not unload the external sink process or prove the implementation bytes behind an approved artifact label.

V13 ProcessHost checkpoint creation requires an operator semantic-retention authority; V12 deployment currently has no shared authority for that path and therefore refuses checkpoint custody from a reloadable factory. Complete active-task/replay lifecycle publication, audit/unstable-replica retirement, fuel-equivalent live wrapper/shim collapse, general adapter execution and safe eventual reclamation remain open. T1-05, T2-04 and the 20/62 task count do not change from this bounded path alone.
