# D11 — Resource-scoped signed sink profile

Status: opt-in implementation profile under V4-T2-04. Specification 0.1.0 acceptance gates and V5/V10 historical bytes remain unchanged.

## Decision and boundary

`aether.signed-effect-resource-policy/6` retains V5's signed repository, AST, epoch, adapter write semantics, artifact label, deadline/clock and sink authority bindings. Each rule adds one bounded argument selector: a non-null index from 0 through 31 in the resource-scoped host/deployment profile. The selected exact tagged argument must be a safe string segment. The resource path is the signed fixed prefix followed by that segment; missing, non-string or invalid segments refuse before broker dispatch. The V5 policy remains the explicit sink-wide profile.

Direct ProcessHost selects `attested-sink-v9-resource-witness` and configuration `/9`. ProcessDeployment selects `scoped-anchored-sink-v11`, state `/11`, prepared `/9` and effect plan `/9`. The operator still supplies the signer, clock, sink anchor, sink state witness and effect/host/deployment witnesses outside the reloadable factory. V11 has its own deployment witness identity and cannot silently reopen a V10 registry or host configuration.

At call admission, the host checks the grant's signature, audience, lifetime and base scope. The guest may compute the selected argument, so the host derives the **concrete** target from the canonical worker effect arguments at `onEffect`. It checks the original grant and revocation against that target before adopting the worker's proposed snapshot or writing an effect intent, and again before broker invocation. The broker request uses `aether.process-effect-grant-ref/2`, binding the host configuration, operation ID, capability, policy epoch and digest of the complete concrete resource path. Recovery reconstructs the same path and grant reference from the retained effect arguments and signed policy, then requires the exact witnessed broker request; it does not redispatch under a fresh grant. Cached results require a separate current authorization check: the host derives each retained target suffix from the witnessed effect row and verifies the caller's grant against that suffix under the **current** generation's base path. An Alice-only grant cannot read Bob's cached outcome.

## Current evidence and limits

The [real worker and deployment campaign](../../../../test/tier4/process-attested-sink-host.test.ts) admits Alice and Bob with distinct grants, proves their broker grant references differ, and refuses an Alice-only write to Bob before a sink effect intent. An invalid path segment also fails without a sink decision. A worker that increments a record before attempting a Bob write under an Alice grant leaves both the host's stored counter and sink decision count unchanged. It rejects Alice-only attempts to read Bob's cached direct and deployed results. Two signed promotions, including one with the same policy digest under a new generation, show that a current-generation Carol grant can read the older Carol result while an Alice grant cannot. V11 deployment state and prepared records reopen after an older local registry is restored.

The [controller crash campaign](../../../../test/tier4/process-attested-sink-controller-crash.test.ts) retains the exact `account/alice` argument and grant-ref `/2` in the witnessed prepared broker request. A real controller `SIGKILL` after sink commit reopens with one sink decision, including after the original grant is globally revoked. A crash before broker dispatch permits authorized abort because the effect witness has no request and the sink has no decision. A crash after broker dispatch starts but before sink entry rejects abort; signed sink status establishes one witnessed `not_committed` fence that permanently refuses late execute, and isolated replay settles the failed effect without redispatch. After that fence, a second recovery revokes only `account/alice`: a fresh broad `account` grant remains valid at call admission but cannot retrieve the cached result because the retained Alice target is checked. The sink and two witnesses run as separate processes under one UID. Historical V10 cases remain in the same campaign. The earlier [exact-source evidence](../evidence/integration-fed67f5/REVIEW.md) covers the postcommit subset; the newer focused campaign records the additional crash phases.

This profile selects only one string path segment. It does not infer targets from opaque payloads, preserve a signed historical grant token in the effect row, or prove a general external API's resource semantics. Cached results recheck the concrete grant after witness inspection to narrow revocation timing, but a strict atomic revocation/result-publication guarantee still needs a shared authority fence. The approved adapter digest remains a label, not measured executable code. Distinct-UID custody, whole-machine rollback resistance, complete budget settlement and all-path hostile-adapter containment remain open. V4-T2-04/G1/G2 and NFR-16 are not verified.
