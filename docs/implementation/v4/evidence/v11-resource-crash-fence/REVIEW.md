# V11 resource-scoped controller crash and fence campaign

Tested from base `3099734843ef5d122e89c71b5880347e0bc074a3` plus the task-owned changes in this checkpoint. The raw [focused test log](focused.log), [typecheck log](typecheck.log), [build log](build.log), and [roadmap check](roadmap.log) are retained. The focused campaign ran with Node 26.7.0 on macOS. Eight process cases passed, zero failed. Build, typecheck and `roadmap:v4:check` passed. A full repository test suite and release benchmark were not run for this checkpoint.

The new V11 cases kill the controller after (1) a resource-scoped host effect intent but before broker dispatch, and (2) broker dispatch begins but before the sink is entered. A fresh controller opens the witnessed deployment. In case 1 the effect witness remains empty, sink revision remains zero, and authorized abort records no external effect. In case 2 another controller tries an unsafe abort before any sink fence exists; the host refuses and both witnessed heads remain unchanged. Independently signed sink status then creates one durable `not_committed` fence; late execute is refused, isolated replay settles the failed effect, and reopening does not add another sink decision. The host and broker retain `account/alice` and the resource-bound grant reference where a broker request exists. Each case uses a real worker, sink service, sink-state witness service and operator witness service in separate processes; all run under one UID.

A third V11 case revokes only `account/alice` after the signed fence. A new broad `account` grant remains valid at call admission and fails when the cached operation checks the retained Alice target. The sink decision count stays one. The existing V10 and V11 postcommit cases pass in the same run. The test changes did not require a production-code fix.

The [first focused run](initial-focused-failure.log) had one test assertion with incorrect abort-reason wording; the implementation returned the safe abort expected by the test. The [first build attempt](initial-build-symlink-failure.log) failed because this isolated worktree initially used a `node_modules` symlink outside its root and the worker bundle correctly rejected the escaped executable input. Local `npm ci` followed by the final build passed.

This proves a bounded same-UID, append-once sink fixture. It does not prove separate-UID custody, real external transaction semantics, measured adapter bytes, complete usage metering, an atomic revocation/read fence, or all effect paths. V4-T2-04 and its G1/G2 acceptance gates remain open.
