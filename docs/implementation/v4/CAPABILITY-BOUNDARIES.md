# Capability containment boundary audit

This is the live coverage map for V4-T2-04/FR-2.4. It names the checks used by the current implementation and the boundaries still needing proof. It is **not** a completed gate or a claim that all possible execution paths have been explored.

**Trusted computing base.** `TopologyHost.allocateRecord`, `ProcessHost.allocateRecord`, `ProcessDeployment.allocateRecord`, grant issuance, the operator signer/epoch anchor, reloadable host factory, broker authorization and Node adapter process are administrative/trusted APIs. They are not tenant-call endpoints in this profile. The import-free V2 adapter profile rejects ordinary module dependency syntax but does not confine `eval`, ambient globals or process privileges. An untrusted caller with the host object or a malicious JavaScript factory is outside the proved boundary. These assumptions must be replaced with stronger isolation before a zero-escape release claim.

The [zero-import WebAssembly experiment](../../../roadmap/v4/research/wasm-adapter-isolation/README.md) narrows one guest's callable import surface and exercises the real broker. It shares a process with trusted JavaScript and does not yet enforce CPU/memory limits or authenticate a separate OS/guest boundary. It is research evidence, not a replacement for the trusted-computing-base assumption above.

The opt-in [V6 isolated Wasm profile](ISOLATED-WASM-PROFILE.md) moves a bounded read-only i32 guest into a disposable child and binds its V3 artifact to signed V4 policy. Its real ProcessHost and ProcessDeployment checks cover wrong adapter/capability, wrong router context, current grants, malformed arguments, trap recovery, reopen and promotion. The trusted parent factory, broker journal/clock and OS remain outside the guest boundary; this narrow profile does not cover general effectful adapters or prove all-path containment.

The opt-in [V7 trusted-clock extension](TRUSTED-CLOCK-PROFILE.md) removes the factory clock from live grant-expiry and signed-deadline decisions. An external operator anchor is bound into deployment `/7`, prepared `/5`, host configuration `/5` and effect plan `/5`. A real frozen-factory-clock test covers direct host and deployment calls, promotion, reopen and a final broker authorization race. The external provider's rollback resistance, broker receipt integrity, parent factory isolation, general adapters and complete path enumeration remain open.

**Gate status.** G1 and G2 remain **in progress**. The boundary matrix supplies real negative tests for direct local and process calls; the named existing tests exercise closures and effects. A release audit must enumerate every supported route, run adversarial fault/revocation schedules on its exact source commit, verify no sink or heap publication on denial, and separately qualify adapter isolation and external epoch authority. NFR-16's probability-zero claim requires an explicit formal model and trusted computing base beyond these finite tests.
