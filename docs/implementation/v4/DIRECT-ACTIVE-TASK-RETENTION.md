# Direct resumable active-task retention (bounded T1-05/G2 slice)

`ActiveTaskSemanticRetention` is an opt-in authority for a direct `ResumableRuntime`. It constructs one `SemanticGarbageCollector` from the same `DurableGraphStore` that it uses to hydrate and validate the execution manifest's module root and every declared external function root. The runtime compiles and validates the manifest before accepting the authority. Immediately before `start()` can publish its first running frame, the authority writes monotone `active-task` retention records and graph leases for those roots, verifies them, then writes a digest-bound marker under the collector directory.

The marker binds the execution ID, compiled program digest, manifest digest, exact module and dependency roots, repository, graph-store and collector directories, and collector configuration. Repeated starts with the same identity validate the marker and pins. `step()`, active `snapshot()`, host mutations while running or blocked, and `restore()` recheck the marker, records, leases, collector profile, and hydratable roots. A missing marker after pin publication is rejected, including on a new runtime instance; it is not recreated. A crash before the marker may leave conservative pins that require operator recovery. No clock grants release.

This authority does not create a checkpoint or make an in-memory snapshot durable. The existing direct checkpoint journal has its own `replay` authority; callers needing both live-task and replay protection must use both opt-in boundaries. The separate-process test kills a worker after start but before any checkpoint journal exists, then collects from a reopened store and restores a snapshot explicitly written by the test. It proves the active roots survive that crash and collection, not a full durable task recovery protocol.

The boundary does not authorize release at completion, general adapter retirement, audit or unstable-replication lifecycle closure, or ProcessHost integration. Existing virtual-forward restrictions at the effect broker and ProcessHost remain in force. This is not T1-05/G2 closure.
