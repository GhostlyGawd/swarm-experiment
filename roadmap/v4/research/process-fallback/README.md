# Effect-aware process fallback candidate (V4-T3-07)

`ProcessFallbackSupervisor` is an opt-in, process-level candidate over one `ProcessHost` state domain. It accepts two executable Aether functions only when their parameter symbols and types, return types, purity, capabilities, surfaces and explicit contract are identical. Both tiers use the real worker/effect broker. A signed, bounded journal binds exact operation IDs, arguments, host identity, manifest and signer. The repair outbox uses stable IDs and at-least-once delivery.

Tier 2 starts only after a Tier 1 failure with durable evidence that no external effect could have committed and the original snapshot/generation still owns the host. ProcessHost checks that base under its journal lock when starting each tier. A requested/rejected/aborted effect can be safely aborted; dispatching, committed or indeterminate effects block automatic fallback. Exact host replay can reconcile a committed effect, after which the supervisor may return the Tier 1 result. Fresh scoped grants are required for each tier and cached successful receipts. A blocked result does not claim a terminal production outcome.

Focused tests cover pre-effect faults, committed-effect faults, both-tier failure, changed heap, grant denial, signed-journal tamper, outbox retry and five real SIGKILL windows. These include death after a durable effect request but before dispatch, and death inside the sink after dispatch began. They assert no duplicate sink call. The candidate returns `productionAuthorized: false`.

This does not supply an independently proved portable Tier 2, complete effect reconciliation policy, native in-frame lowering, or the required ≤50 ns maximum. The measured bounded native switch remains an 83.333 ns miss. V4-T3-07 and its release gates remain open.

## Opt-in proved conservative V2

`ProcessFallbackSupervisor` now accepts an exact independent portable certificate for a **pure scalar Tier 2** while Tier 1 may be effectful. Both tiers retain identical arguments, return type and formal contract; the conservative tier has no capabilities or tuning surfaces. The checked proof digest is bound into `aether.process-fallback-profile/2`, and new histories use `aether.process-fallback-journal/2`. V1 histories and their bytes remain explicit. A changed or missing certificate cannot silently reopen a V2 history.

After a Tier 1 fault with no possible external commit, actual ProcessHost Tier 2 execution starts from the unchanged base snapshot with fresh invocation authority. Under separately authorized `isolated-replay` recovery, V2 opts into `reconcileBroker: true`: an indeterminate Tier 1 effect first asks its durable broker for the original exact request and trusted adapter disposition. V1's historical manual-reconciliation behavior is unchanged. A dead broker writer ticket is released only after PID death is checked. A committed effect replays Tier 1 without redispatch. A trusted adapter's definitive terminal noncommit permits Tier 2; `unknown`, a live writer or mismatched request remains blocked. The asynchronous repair outbox remains idempotent across process death.

The [real-worker tests](../../../test/tier4/process-fallback-proof.test.ts) cover exact proof and journal binding, edited proof rejection, revoked Tier 2 authority, coordinator SIGKILL before Tier 2, SIGKILL after a committed sink, SIGKILL before the sink with definitive noncommit, and SIGKILL after the sink with unknown status. These tests use a trusted local adapter that reports `not_committed` only for a fixture known to have stopped before its sink write. They do not authenticate a remote sink's claim or establish formal effect semantics. The profile still returns `productionAuthorized: false`; Tier 2 source proof is limited to the scalar fragment. Full native in-frame switching, broader value/effect coverage and the unchanged ≤50 ns release gate remain open, so T3-07 is not verified.
