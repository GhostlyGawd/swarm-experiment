# Fuel-preserving wrapper shortlist: critique, then reconstruction

Status: critique and reconstruction are **design judgments**, not correctness proofs. The frozen generation set is [generation.md](generation.md) plus [mutations-and-combinations.md](mutations-and-combinations.md). All eight concepts below were critiqued before any redesign was written. Fixed requirements remain exact finite-fuel faults, public frame/trace/fault data, effects/contracts and replay identities.

## Critique of the full shortlist (completed before reconstruction)

| Canonical ID | Specific failure path and weakest dependency | Who loses; observation that disproves it |
| --- | --- | --- |
| M01 ordered event tariff | A static list may debit wrapper steps before original argument/contract evaluation or omit a frame-dependent fault; a call may reach the sink under the wrong quota. Weakest dependency: deriving the exact ordered source transition stream for every selected wrapper shape. | Caller/sink safety; one differential `maxSteps`/trace/contract counterexample disproves the mapped tariff. |
| M02 guarded source fallback | A guard that itself ticks or uses a stale fuel estimate changes the boundary it is trying to protect; route choice after crash may differ from the original. Weakest dependency: an unobservable, signed route decision bound to checkpoint/replay. | In-flight task and sink; one low-budget call or restart selecting a different route disproves it. |
| M04 isolated paired execution | An effect can escape either lane before reconciliation, or crash recovery can publish the buffered intent twice. Running source and target increases latency and resource use. Weakest dependency: a genuinely isolated, exactly-once external-effect barrier. | External service and budget owner; duplicate sink decision or unequal retained state disproves it. |
| M07 shared semantic doorway | A mutable alias table could redirect a symbol after a receipt is signed; a doorway that merely runs the archived wrapper may rename rather than collapse the abstraction. Weakest dependency: manifest-bound, independently verified virtual frame behavior with a smaller live execution graph. | Replay/audit reader; wrong symbol/frame on an old receipt or no actual live graph reduction disproves it. |
| M09 defunctionalized continuation | Prelude/epilogue token may be lost or consumed twice across suspension, especially if the target faults after an external effect. Weakest dependency: one durable linear token state at every call boundary. | Resuming task and sink; duplicate postlude/effect or missing fault binding after SIGKILL disproves it. |
| M11 source logical PC | One target instruction can correspond to several source transitions with dynamic branches; a missing mapping silently shifts fuel and effect order. Weakest dependency: complete cost/trace simulation across interpreter, compiler and resumable engine. | Every caller; one unsupported AST kind, recursive call or quota boundary disproves the full-runtime claim. |
| M12 typechecked stutter skeleton | Inserting ordinary no-op AST around a direct call can move argument evaluation relative to quota faults and cannot synthesize the old call depth/bindings on its own. Weakest dependency: representing a virtual frame without a new semantic primitive. | Caller and debugger; baseline budgets 11–12 or missing depth-3 call trace disprove a naive skeleton. |
| CO01 proof + doorway + cohorts | Even if each component works separately, a promotion could bind a new doorway before old continuations are frozen, or a proof could certify the wrong generation. Weakest dependency: one durable handoff spanning proof, active alias and checkpoint identities. | In-flight tasks and old receipt readers; cross-generation replay mismatch or source effect redispatch disproves it. |

### Fresh critique of replacement M13

M13 inserts a new semantic `VirtualCall` instruction in the candidate AST. It may preserve fuel and trace in the reference interpreter yet be ignored or lowered differently by Agent-IR, ProcessHost, the resumable compiler or native code. Its weakest dependency is **all-path lowering and exact proof of the instruction's source transition semantics**. A candidate that passes the reference baseline but changes one process effect ID or checkpoint digest is disproved. This critique is separate from M12's failed AST-only mechanism.

## First technical test protocol and observation

Hypothesis: **M01 revision 2**, for an empty-contract, one-argument pure Int wrapper, can replace a live wrapper declaration with a direct target call plus an archived-AST-derived ordered virtual frame/tick/trace script while matching the source under every tested finite budget.

- Boundary: reference `Runtime` only; one exact wrapper and an effect after its return. Excludes portable proof issuance, ProcessHost, resumable execution, general values, nonempty contracts and native code.
- Inputs: Int `-1`, `0`, `3`; `maxSteps` 1–64 for each input, **192 trials per source and prototype condition**, 384 raw runs overall. The source fixture is [baseline.ts](baseline.ts), expanded without changing its existing 32-case evidence.
- Primary pass measure: for each paired trial, exact equality of returned value/fault kind and bindings, consumed step count, full ordered trace including depth, `onStep` callbacks, and effect log/sink count. **192/192 prototype pairs** must match the source; one mismatch rejects the current M01 implementation revision. Diagnostic measures: candidate current-AST size, metadata bytes, runtime wall time and archive reads, reported separately without a passing threshold.
- Resource estimate: local Node process and one existing developer/agent; setup and run time unknown until measured, no paid service or participant needed.
- Failure decision: if a mismatch is caused by the event script's position, redesign M01; if caused by missing wrapper state, compare M07/M09; if only a backend differs later, do not extrapolate the reference result to production.

**Observed bounded result:** [virtual-prototype.ts](virtual-prototype.ts) removes the wrapper from the current candidate module, derives a four-transition prelude from the archived exact pure tail-forwarder AST, and installs a research-only virtual frame through private `Runtime` methods. [prototype-results.json](prototype-results.json) records **192/192 exact paired matches and zero failures**; [verify-prototype.ts](verify-prototype.ts) reruns the source in a fresh Node process and checks the raw result bytes, exact case count, archive absence in the candidate, and descriptor digest. A changed prelude descriptor is rejected. The test ran locally with `node --experimental-strip-types roadmap/v4/research/semantic-gc-fuel/verify-prototype.ts` and exited 0. This does **not** validate a public AST node, independent portable certificate, compiled/resumable/ProcessHost semantics, persistence, effect-ID stability, source-to-candidate promotion or controller crashes. M01 remains a research concept, not a T1-05 gate.

## Maintainer-use test (pending participants)

Target participants are Aether maintainers who approve GC promotions; no recruitment or contact is authorized or completed. The behavior to measure is whether the proof/trace artifact lets a maintainer correctly reject an unsafe wrapper rewrite and distinguish it from a safe one, not whether they like the design. Prepare two exact code cards (source and candidate), one seeded quota/effect divergence and one certified matching case after the technical prototype exists. Each participant would inspect both cards with and without the event certificate, state an approve/reject decision and name the decisive trace/fuel evidence. Capture sheet fields per card: participant ID, condition, source/candidate digest, decision, ground-truth correctness, decisive evidence named, elapsed seconds, and certificate-use compliance. No sessions or success claims exist; task cards, counts, thresholds and time budget remain to be finalized once a functioning certificate is available.

Five-category prior-art review and an admitted implementation remain pending. This scorecard may change after inspected sources or failed tests; no novelty or defensibility claim is made.
