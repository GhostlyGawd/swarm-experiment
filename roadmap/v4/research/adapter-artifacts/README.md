# Trusted adapter artifact provenance foundation

`src/tier2/adapter-artifact.ts` loads trusted JavaScript effect adapters. Its descriptor binds one capability, adapter ID, declared broker semantics and the SHA-256 of the exact source bytes. The loader copies caller-owned descriptor bytes before its first await, checks the source hash and UTF-8 bytes **before** importing those same bytes through a `data:` URL, then verifies the exported descriptor and freezes the returned adapter. A module-local brand records the captured artifact digest; copying the object does not copy that provenance.

New `aether.effect-adapter-artifact/2` descriptors also sign `aether.adapter-js-import-free/1`. Acorn parses the exact copied bytes as a complete ES module before evaluation. Static imports, dynamic imports, re-exports from another module, `import.meta` and unsupported syntax refuse admission before any adapter or dependency code runs. Strings and comments containing import text remain ordinary source. [Acorn's parser and walker](https://github.com/acornjs/acorn/blob/master/acorn/README.md) are pinned runtime dependencies. The focused tests prove zero top-level side effects on refused imports, exact descriptor binding and broker retry behavior.

The expected artifact descriptor must come from an independently approved execution policy. Computing a hash of caller-supplied code and then approving that same code is not authorization. Signed effect resource policy **v3** binds the V2 artifact digest; fresh `scoped-anchored-v5` ProcessDeployment histories require both, plus an independently provisioned signer anchor. ProcessHost reads the actual branded adapter from a broker-backed router before sink dispatch. Old V1 descriptors keep their exact digest and import-capable behavior only through `legacyAdapterArtifactForSource` and an explicit `admitAdapterSource(..., { legacyProfile: 'aether.adapter-js-legacy-v1/1' })` call. Historical signed-policy V2/anchored-v4 deployment state retains its own explicit compatibility profile and bytes.

The imported code still runs with normal Node process privileges. The V2 parser closes ordinary module syntax dependencies; trusted JavaScript can still reach ambient globals, `eval`/`Function` and process resources. It is **not** a hostile-code sandbox or a proof of declared adapter semantics. Node's own Permission Model documentation says it does not protect against malicious code, so enabling that flag alone would not close this boundary. [Node Permissions](https://nodejs.org/download/release/v26.7.0/docs/api/permissions.html). An OS/guest-isolated or otherwise constrained production adapter runtime remains open.

The V3 policy digest is bound into the approved execution manifest. Changed, unbranded or import-capable artifacts fail before the live sink under the new default. Signed V2/V3 hosts use nonvirtual broker bind, mode, identity and invoke methods backed by JavaScript-private router state. This closes a reproduced subclass override that previously displayed an approved adapter identity while calling an unapproved sink without a durable broker dispatch. V4-T2-04 still needs hostile-adapter isolation, external epoch rollback protection, signer rotation and a complete all-path campaign. The trusted factory and Node process remain part of the declared computing base.
