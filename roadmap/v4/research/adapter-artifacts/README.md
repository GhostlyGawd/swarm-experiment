# Trusted adapter artifact provenance foundation

`src/tier2/adapter-artifact.ts` adds a versioned, opt-in loader for trusted JavaScript effect adapters. Its artifact descriptor binds one capability, adapter ID, declared broker semantics and the SHA-256 of the exact source bytes. The loader copies and validates caller-owned descriptor bytes before its first await, checks the source hash and UTF-8 bytes **before** importing those same bytes through a `data:` URL, then verifies the exported adapter descriptor and freezes the returned adapter object. A module-local brand records the captured artifact digest; copying the object does not copy that provenance. Focused tests mutate the caller descriptor during import, dispatch the loaded adapter through the real durable effect broker and confirm a same-ID retry reuses its receipt.

The expected artifact descriptor must come from an independently approved execution policy. Computing a hash of caller-supplied code and then approving that same code is not authorization. Signed effect resource policy **v2** additionally binds this source artifact digest, and the default `scoped-artifact-v4` ProcessDeployment profile requires v2 for effectful modules. ProcessHost reads the actual branded adapter from a broker-backed router before sink dispatch. Earlier signed policy v1 and unsigned scoped profiles remain explicit compatibility choices.

The imported code runs with normal Node process privileges. Node supports `data:` ESM imports and does not resolve relative imports from them, but absolute and builtin imports remain possible. [Node ESM documentation](https://nodejs.org/api/esm.html) describes this behavior. The loader does not confine module side effects or verify that the implementation honors its declared semantics. Node explicitly says `node:vm` is not a security mechanism, so this profile makes no untrusted-code sandbox claim. [Node VM documentation](https://nodejs.org/api/vm.html) states that boundary.

The v2 policy digest is bound into the approved execution manifest, and altered/unbranded adapter bytes fail before the sink. Remaining integration work includes an operational isolation policy, independent signer trust, dependency closure and end-to-end adverse sink campaigns before V4-T2-04 can close. The trusted factory and Node process retain authority to run the approved module and its absolute imports.
