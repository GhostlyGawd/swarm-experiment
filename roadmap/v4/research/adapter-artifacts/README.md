# Trusted adapter artifact provenance foundation

`src/tier2/adapter-artifact.ts` adds a versioned, opt-in loader for trusted JavaScript effect adapters. Its artifact descriptor binds one capability, adapter ID, declared broker semantics and the SHA-256 of the exact source bytes. The loader checks the hash and UTF-8 bytes **before** importing those same bytes through a `data:` URL, then verifies the exported adapter descriptor and freezes the returned adapter object. A module-local brand records the artifact digest; copying the object does not copy that provenance. A focused test dispatches the loaded adapter through the real durable effect broker and confirms a same-ID retry reuses its receipt.

The expected artifact descriptor must come from an independently approved execution policy. Computing a hash of caller-supplied code and then approving that same code is not authorization. Current signed effect resource policy v1 binds adapter ID and semantics digest; it does **not** yet bind this source artifact digest. ProcessDeployment therefore cannot claim code-provenance admission from this loader alone.

The imported code runs with normal Node process privileges. Node supports `data:` ESM imports and does not resolve relative imports from them, but absolute and builtin imports remain possible. [Node ESM documentation](https://nodejs.org/api/esm.html) describes this behavior. The loader does not confine module side effects or verify that the implementation honors its declared semantics. Node explicitly says `node:vm` is not a security mechanism, so this profile makes no untrusted-code sandbox claim. [Node VM documentation](https://nodejs.org/api/vm.html) states that boundary.

Next integration work is a new signed policy version that includes the artifact digest, requires loader-branded adapters at the final dispatch boundary, and binds those bytes into the approved manifest. A production adapter still needs an operational isolation policy, signer trust, dependency closure and end-to-end adverse sink tests before V4-T2-04 can close.
