# Executable projection V11: pure scalar calls in contracts

V11 admits a direct `Call` in `requires` and `ensures`, including a call inside `old(…)`. The callee and its transitive direct call graph must be synthesized, declared pure, capability free, and closed over direct calls. Every callee takes and returns scalar projection types. Contract expressions still reject `Invoke`, `SeqMap`, `SeqFold`, `Lambda`, `Apply`, `Spawn`, and `Await`; a reachable callee containing one of those nodes is rejected. This is a restricted executable source profile, not a change to the Aether AST or type checker.

The [V11 test](../../../../test/projection/contract-calls.test.ts) compares the reference runtime with actual TypeScript, Python, and Rust execution. It checks a precondition call, a postcondition call after local mutation, a transitive helper call, `old(Call(…))`, failed preconditions and postconditions, source edits, exact-root local and imported parsing, and rejection of effectful, unsynthesized, and indirect callees. The full projection suite passed 84/84 tests. The parent build task owns the final full-tree typecheck and integration checkpoint because ProcessHost changes were underway concurrently.

V11 selects only when a module or exact-address dependency contains a contract `Call`. A comparison against the pre-V11 `dba08a8` source emitted byte-identical source, runtime, and dependency maps for V2, V7, and V10 fixtures in all three targets. This change does not close V4-T1-02: blockless bindings and other valid restricted contexts remain to audit, and the required 4× token result remains unmet.
