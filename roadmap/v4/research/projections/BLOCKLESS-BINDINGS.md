# Executable projection V12: blockless bindings

V12 projects a `Let` directly beneath `If`, `While`, or `Atomic` without adding a `Block` to the AST. The Aether reference runtime writes such a binding into its current function or block scope. Native TypeScript and Rust braces would otherwise hide it; Python's function-wide names would also confuse separate Aether block scopes. V12 emits one uniquely named optional slot per local symbol and lexical Aether scope. A read uses that slot if bound, falls back lazily to the nearest outer binding, or raises `unbound`. A later `Assign` writes the nearest bound scope; if none is bound, it creates the binding in the current scope. The slot and conditional assignment scaffolding is visible and checked by exact source regeneration.

The [focused tests](../../../../test/projection/blockless-bindings.test.ts) establish exact AST-root round trips in all three targets, altered-body root changes, scaffolding rejection, exact-address dependency closure, and execution in actual TypeScript, Python, and Rust against the reference runtime. Cases cover both `If` branches, a skipped branch with an unbound read, repeated loop binding, direct `Atomic` binding, later assignment, parameter and block shadowing, assignments before a local shadow, an assignment made in a temporary block after a skipped outer `Let`, and an `Atomic` fault. The V12 profile is selected automatically only when an entry or exact-address dependency contains a blockless `Let`; older explicit projection versions keep their rejection behavior.

The prior `b427373` source and V12 source were compared on one unchanged module for explicit V2, V7, V10 and V11 source in all three targets, plus automatic source and runtime in each target: **18/18 byte-identical outputs**. The focused projection suite passed **92/92 tests**, and `npm run typecheck` passed on the edited worktree before commit. These are compatibility checks for those fixtures, not a claim that every older source is proven byte-identical.

This slice does not establish all Aether projection semantics: the exact-root fixture covers the tested restricted programs, while other valid statement, contract, continuation, and deployment combinations still need differential testing. V12 also does not change the FR-1.2 token-density result or close V4-T1-02.
